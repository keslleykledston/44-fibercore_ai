# Codex Adversarial Review

Target: branch diff against main
Verdict: needs-attention

No-ship: leitura única pode aceitar arquivo truncado e registrar hash de evidência incompleta; a validação de endereço também deixa escapar IPv6 não comprimido com porta.

Findings:
- [medium] Uma única leitura pode validar e hashear apenas parte do H1 (apps/api/app/cli.py:194-198)
  `os.read` pode retornar menos bytes que o solicitado, mesmo antes do EOF. O código então verifica tamanho, conteúdo e SHA-256 somente desse prefixo e grava o vínculo como sustentado pelo H1, embora o arquivo referenciado possa conter conteúdo adicional, inclusive um endereço ou credencial fora do trecho lido. O limite de 256 KiB também pode ser contornado por essa leitura parcial. Leia até EOF, acumulando no máximo 256 KiB + 1 bytes, antes de validar e calcular o hash.
  Recommendation: Substitua a leitura única por um loop até EOF que acumule no máximo 256 KiB + 1; rejeite ao exceder o limite e valide/hash somente o conteúdo completo.
- [medium] IPv6 completo com porta não é reconhecido como endereço (apps/api/app/cli.py:203-210)
  A expressão de tokens captura os caracteres hexadecimais, pontos e dois-pontos, mas descarta os colchetes. Para `[2001:db8:0:0:0:0:0:1]:443`, o token passa a incluir `:443`, formando nove grupos IPv6; `ip_address` rejeita esse token e o código não tenta validar o endereço interno sem a porta. A regex IPv4 separada não cobre esse caso, então um H1 com IPv6 explícito e porta pode ser aceito apesar da regra de rejeição. O teste cobre IPv6 comprimido, cujo token interno ainda é detectado, mas não esta forma completa.
  Recommendation: Detecte e valide separadamente `[IPv6]:porta` extraindo o conteúdo entre colchetes e verificando que a porta está no intervalo válido; inclua um caso IPv6 não comprimido no teste.
