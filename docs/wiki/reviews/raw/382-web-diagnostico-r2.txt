# Codex Adversarial Review

Target: branch diff against main
Verdict: needs-attention

Não ship: a trava persistida pode ser removida por uma execução antiga ou por uma leitura parcial; os 403 agora distinguem feature_disabled de falta de permissão.

Findings:
- [high] Uma execução antiga destrava um pedido novo (apps/web/src/components/PingTestSection.tsx:64-66)
  `known` é capturado antes do POST e a trava é removida quando qualquer ID da resposta não estiver nessa lista. Se outra pessoa criar uma execução depois dessa captura, mas antes ou durante o POST, a próxima leitura encontra esse ID e libera o botão mesmo sem confirmar o pedido atual. Como cada clique usa uma chave de idempotência nova, o usuário pode enviar um segundo teste enquanto o primeiro pedido ainda está sem confirmação.
  Recommendation: Registre o instante/identificador do pedido e só considere novas execuções criadas após esse instante, ou vincule o POST a uma chave que a lista de execuções devolva; não destrave por qualquer ID ausente da lista capturada.
- [medium] Falha parcial no GET de capacidades e execuções pode ocultar o erro (apps/web/src/app/bff/cpes/[id]/ping/route.ts:11-19)
  O BFF consulta capacidades e execuções em paralelo, mas, se qualquer uma falhar, escolhe `bad` com base apenas em `c.status !== 200`. Quando capacidades respondem 200 com corpo inválido/ausente e runs falham com 403, 404 ou 401, essa condição escolhe `c` e retorna `failed`/502 em vez do erro real. O cliente então apresenta uma falha genérica, inclusive podendo mascarar falta de permissão ou sessão expirada.
  Recommendation: Valide cada resposta independentemente e propague o status/`detail` da resposta que falhou; trate corpos inválidos como 502 somente quando ambos os endpoints responderem com sucesso.
