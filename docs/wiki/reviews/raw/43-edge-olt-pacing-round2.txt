# Codex Adversarial Review

Target: branch diff against main
Verdict: needs-attention

Do not ship yet: corrupted state does not protect default-paced SNMP, and the persisted guard does not coordinate concurrent processes or reliably retain extended cooldowns after a save failure.

Findings:
- [high] Corrupt state does not pace default SNMP collections (agents/edge/internal/collector/olt.go:203-208)
  When loading fails, an unknown device is deferred only if `src.Interval > 0`. SNMP defaults to `Interval == 0`, so the first call rewrites the file and skips once, but the next collection call proceeds immediately. A corrupt or unreadable guard can therefore lead to repeated SNMP collections after restart, contrary to the fail-closed recovery behavior described in the change.
  Recommendation: On corrupt state, enforce a recovery delay for every transport, including default-paced SNMP; persist a future eligible time or require an explicit safe recovery interval before allowing I/O.
- [high] Separate processes can bypass the shared guard file (agents/edge/internal/collector/olt.go:180-223)
  The mutex protects only one `OLT` instance. Each process loads the JSON once, then independently checks and saves it; atomic rename prevents torn files but does not serialize the read-check-write sequence. If two Edge processes overlap, both can observe the device as due, persist their own state, and log in or query the same OLT concurrently. The guard file itself provides no inter-process lock, and the binary does not enforce singleton execution.
  Recommendation: Serialize the entire load/check/reservation/update operation across processes with a lock associated with the guard path, or enforce a singleton process before any collector can run.
- [medium] A failed cooldown save can erase a longer cooldown on restart (agents/edge/internal/collector/olt.go:229-234)
  After a failed collection, cooldown persistence is best-effort. If that save fails after the pre-I/O `Last` write succeeded, a restart retains only the attempt timestamp. With default SNMP pacing (`Interval == 0`), it can immediately retry; with a configured interval shorter than `Cooldown`, it can retry as soon as the interval elapses instead of honoring the cooldown. This can recreate the retry pressure the cooldown is meant to stop.
  Recommendation: Make failure cooldown persistence part of the guarded failure path and fail closed across restarts if it cannot be committed; alternatively persist a conservative cooldown deadline before I/O so restart recovery cannot retry early.
- [medium] Hostname and IP aliases still create separate device keys (agents/edge/internal/config/config.go:215-224)
  `DeviceKey` normalizes IP literals and lowercases hostnames, but does not resolve hostnames. An SSH entry using an OLT hostname and an SNMP entry using that same OLT's IP therefore pass the duplicate-device check and receive different guard keys. They can bypass each other's interval, cooldown, and lock and issue concurrent requests to the same physical OLT.
  Recommendation: Require one canonical configured identity shared across transports, or resolve and validate aliases against a stable device identity at configuration time; reject entries whose resolved endpoint is already configured.
