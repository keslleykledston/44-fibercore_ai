Findings:
- [high] A comparação de ordenação usa timestamps de relógios diferentes (apps/api/app/api/profile_studio.py:189-191)
  O cache recebe `asked_at` de `row.created_at` (criado na nuvem), mas snapshots gravam esse valor em `observed_at`; o sync compara então `got.asked_at` com `max(observed_at)`. A lógica funciona para snapshots deste caminho quando os timestamps conservam o mesmo valor, mas fica vulnerável quando um snapshot `edge_read` é atualizado por outro fluxo que use `observed_at` como hora de leitura/recebimento ou quando o dado vem de relógios divergentes. Nesse caso, uma leitura antiga pode passar (ou uma válida ser recusada), e a aplicação de perfis ausentes pode marcar perfis como desconhecidos incorretamente. Compare sempre `asked_at` com um campo que represente a pergunta anterior, persistido explicitamente; não use `observed_at` sem garantir que tem a mesma semântica em todos os escritores.
  Recommendation: Persistir `asked_at` como campo próprio nas snapshots sincronizadas e usar esse campo para a checagem `older_than_applied`, com desempate determinístico para leituras simultâneas.
