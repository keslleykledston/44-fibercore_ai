# Codex Adversarial Review

Target: branch diff against main
Verdict: needs-attention

Do not ship yet: applied-state persistence does not enforce the ADR’s private ownership boundary, and a corrupt store can silently erase anti-rollback history before a delivery is accepted.

Findings:
- [high] Applied store accepts files and parent directories accessible to other users (agents/edge/internal/oltsecrets/applied.go:64-77)
  `load` checks only that the applied file is regular and has no group/other permission bits. It does not verify file ownership or the parent directory’s ownership and permissions, then reads with `os.ReadFile`; `Record` can create the parent with `MkdirAll(0700)` but does not tighten an existing directory or validate the resulting file. A pre-existing writable/shared directory or a file owned by another user can therefore expose or let another local user replace/remove this replay and anti-rollback state. Replacing or deleting it resets the delivery-ID and `last` history, allowing a still-valid older signed delivery to be applied again. Validate the directory and file using the same ownership/private-mode and no-follow checks as the credentials and seal-key files, and fail closed on mismatch.
  Recommendation: Require a private, Edge-owned parent directory and a regular Edge-owned 0600 file; open with no-follow semantics, validate the opened descriptor, and reject insecure existing state before reading or writing.
- [medium] Corrupt-store recovery discards anti-rollback history and proceeds immediately (agents/edge/internal/oltsecrets/applied.go:79-109)
  When JSON is malformed, `load` renames the store aside and returns an empty store; `Check` then treats the delivery as new, and `Process` continues to write credentials and record it. This is explicitly documented as limiting rollback only by expiry, but under the ADR’s still-valid replay/stale threat model, corruption (including truncation or tampering) erases `Last` and permits an older signed delivery to overwrite current credentials. Since the next delivery is not necessarily newer, the reset is a live rollback path rather than merely lost diagnostics. Fail closed for applications after detecting corruption, or preserve/restore a trustworthy monotonic anti-rollback anchor before accepting deliveries.
  Recommendation: Return `ErrStateUnreadable` after moving aside a corrupt file and require explicit operator recovery/reinitialization, or store the monotonic per-target expiry state in a protected integrity-checked mechanism that cannot be reset by malformed input.
